# Spray Card Analyzer – API Documentation

## Overview
The **Spray Card Analyzer** module provides functionality to quantify spray coverage on agricultural spray cards.  
It converts an input image into grayscale, performs thresholding to separate sprayed (non-white) areas from the background, divides the card into user-defined vertical sections, and computes the percentage coverage for each section.  
The results can be saved as a high-resolution annotated image for reporting or further analysis.

The module is centred around a single public class `SprayCardAnalyzer`. All functionality is exposed through its methods and publicly accessible attributes detailed below.

## Quick-start Example
```python
from spray_card_analysis import SprayCardAnalyzer

# Path to the spray card image (JPEG/PNG/TIFF …)
image_path = "/path/to/spray_card.jpeg"

# 1. Create an analyzer instance
analyzer = SprayCardAnalyzer(image_path)

# 2. Run the processing pipeline
analyzer.convert_to_grayscale()
analyzer.apply_threshold()
analyzer.analyze_sections(sections=10)  # change sections as needed

# 3. Persist a high-resolution visualisation (optional)
#    The file will be saved next to the input image with "_analyzed.jpeg" appended.
analyzer.save_visualization()

# 4. Access the numerical results programmatically
print(analyzer.non_white_areas)  # List[float] – coverage percentage per section
```

Running the full script is also possible:
```bash
python spray_card_analysis.py  # remember to edit the image path inside the script first
```

## API Reference
### `class SprayCardAnalyzer(image_path: str)`
Represents a single spray card and exposes methods to analyse its spray coverage.

| Attribute | Type | Description |
|-----------|------|-------------|
| `image_path` | `str` | Absolute or relative path to the card image provided at instantiation. |
| `original_image` | `PIL.Image.Image` | The raw image as loaded by Pillow. |
| `gray_image` | `np.ndarray \| None` | Grayscale version generated by `convert_to_grayscale()`. |
| `thresholded_image` | `np.ndarray \| None` | Binary image where sprayed areas are < 255 after `apply_threshold()`. |
| `visualized_image` | `np.ndarray \| None` | 3-channel BGR image annotated in `analyze_sections()`. |
| `non_white_areas` | `List[float]` | Percentage of sprayed pixels for each analysed section. Populated by `analyze_sections()`. |

#### `__init__(image_path: str)`
Initialises the analyzer and loads the image. The actual analysis is performed by calling the public methods below.

---
#### `convert_to_grayscale() -> None`
Converts `original_image` to grayscale using OpenCV and stores the result in `gray_image`.

Example:
```python
analyzer.convert_to_grayscale()
```

---
#### `apply_threshold() -> None`
Applies Otsu's global thresholding to `gray_image`, producing a binary mask stored in `thresholded_image`.

```python
analyzer.apply_threshold()
```

---
#### `analyze_sections(sections: int = 10) -> None`
Splits the thresholded image into `sections` equally-sized vertical slices (default **10**). For each slice it calculates the spray-coverage percentage (non-white pixels) and appends the value to `non_white_areas`.

The method also creates `visualized_image`, an RGB image where each section is framed and annotated with the computed percentage.

```python
analyzer.analyze_sections(sections=5)
print(analyzer.non_white_areas)  # e.g. [12.3, 9.8, 15.0, 11.7, 14.2]
```

---
#### `save_visualization(filename: str = "thresholded_image_with_sections.png") -> None`
Saves `visualized_image` at **400 DPI** with tight bounding and no padding.  
The file is placed in the same directory as the original image and suffixed with `_analyzed.jpeg` regardless of the `filename` argument (the argument is currently ignored in the implementation).

```python
# After analyse_sections()
analyzer.save_visualization()
```

## Advanced Usage Tips
* **Custom Section Counts** – Tune `sections` based on card width and required granularity. More sections yield finer spatial resolution at the cost of additional labels.
* **ROI Masking** – Pre-crop or mask the input image before analysis if you want to exclude borders or text areas.
* **Batch Processing** – Wrap the above workflow in a loop over multiple file paths to process whole datasets.
* **Headless Servers** – Use the provided installation instructions with the headless OpenCV build to avoid X-server dependency errors.

---

## Limitations
* The current implementation considers anything that is not pure white (`pixel < 255`) as spray. Lighting conditions and scanner quality can therefore influence results. Consider pre-processing steps (e.g. background correction) if necessary.
* The helper parameter `filename` in `save_visualization()` is presently unused in the path generation; overriding it does not change the output path.
